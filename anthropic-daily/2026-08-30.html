The GPT retires.
The template ships.

Two products moved on Sunday. One was erased; one was born. Both are wrapper-economy plays and both landed in the same 24-hour window, which is less a coincidence than a signal about where AI distribution is heading.

OpenAI shuttered the DALL-E GPT, the first-party image-generation wrapper that shipped alongside the GPT Store. Not a deprecation notice with months of runway. An endpoint. Images stored in its conversation history were available for download through August 30, then gone. Users who navigate there now get a redirect to ChatGPT Images, the native interface running on gpt-image-1.

Same day, xAI shipped template sharing for Grok Bot: any user can package a Bot's configuration, memories, skills, and X platform integrations into a shareable link. One click installs it. No marketplace approval. No code required. And Anthropic reset the Claude Code limits clock: the temporary 50% usage boost expires September 14, settling at a permanent 25% above the original baseline.

OpenAI, xAI

Sunday, August 30. OpenAI removed the DALL-E GPT from ChatGPT. Not retired with a transition period. Removed. Users who navigate to it see a prompt to switch to ChatGPT Images, which runs on gpt-image-1 and gpt-image-1-mini. Images already stored in the DALL-E GPT conversation history were available for download through the cutoff. After that: gone.

The mechanism is worth naming precisely. This was not the deprecation of DALL-E as a model. It was the retirement of the DALL-E GPT, the first-party OpenAI-authored GPT that appeared pre-installed in every ChatGPT account when the GPT Store launched in January 2024. Third-party GPTs with image generation enabled are unaffected. What died is the flagship first-party use case: the proof-of-concept for why GPTs existed in the first place.

The blast radius reaches everyone who linked to it in a tutorial, built a workflow that started from it, or used it as the exemplar in a pitch deck about the GPT Store. Also anyone whose mental model of what GPTs are for was anchored to that use case. Which is a lot of people, because that use case was the headline.

The GPT Store launched with enormous fanfare. OpenAI projected it would give ordinary users a way to build and distribute AI software without writing a line of code. Two years later, the use cases that worked became features, and the use cases that did not stacked up as abandoned wrappers. The Store is still live. The flagship first-party GPTs that anchored it are disappearing one by one into the native product, which is a more honest description of what GPT-as-feature-prototype always meant.

The pattern is more interesting than the single event. Across 2026, OpenAI has absorbed GPTs-as-wrappers back into first-party features, one at a time. Memory went native. Deep Research went native. Image generation went native. Each time, the wrapper that existed because the underlying product could not yet do the thing got replaced by the product doing the thing. The wrapper tier is becoming a staging area: the place features go before they are real, not the place you build a business.

The read: a GPT that existed because ChatGPT could not generate images is now a dead end because ChatGPT can. The GPT Store was a staging area for capabilities, not a platform for products. OpenAI is clearing it of completed migrations. The wrappers that survive will be the ones that add something the native product still cannot do. That set is shrinking.

Meanwhile, xAI did the exact opposite. The same weekend, Grok Bot shipped template sharing: any user can package a Bot's full configuration, including instructions, selected memories, active skills, and first-party X platform integrations, into a shareable link. Recipients install it in one click. No marketplace. No approval. No developer account required. Early community templates included a multi-role project manager coordinating Notion workflows and a home-robotics controller for a Segway mower.

The comparison to the old GPT Store is obvious and xAI knows it. The meaningful differences: no curation gatekeeping, deeper integration with first-party platform tools, and a moat that no other lab can replicate. The Grok Bot and X native integration that also shipped this weekend is the thing that makes the templates worthwhile. Authenticated, account-aware access to X posts, the user's timeline, and their mentions is not a connector. It is a vertical. xAI owns the social platform and built the integration themselves. No other lab can offer the same capability, because no other lab owns X.

The builder's move: audit any production workflow that routes through an OpenAI-authored GPT. The DALL-E GPT is at least the fourth first-party GPT absorbed into native ChatGPT in 2026. The pattern is clear enough to plan around. For Grok Bot templates: the mechanic paired with real-time X account access is genuinely new territory. A non-developer can now build and distribute an X-aware assistant without touching any code. Whether the audience for that is large is still an open question. Whether the capability exists is not.

Also Shipped
Sunday sweep
Anthropic, Claude Code
The Code Limits Reset

Via @ClaudeDevs on August 29, Anthropic confirmed the new steady-state for Claude Code weekly limits. The temporary 50% above-baseline boost, running since Q2, ends September 14. The replacement: a permanent 25% above the original baseline. Net change from current levels: about 17% fewer tokens per week.

The mechanism is a weekly rolling ceiling at the plan level. Pro, Max, Team, and Enterprise seat plans all receive the same 25% permanent uplift. The cadence (weekly, not daily) does not change; the ceiling does.

The blast radius is precisely the builders who calibrated into the temporary high. A 17% reduction from today's ceiling is enough to push a large refactor from one session to two. Pro and Max accounts that run close to the weekly cap regularly are the ones most likely to feel it. Enterprise users on seat plans face the same percentage change but typically carry larger absolute allocations.

The contrast: OpenAI's Codex CLI shipped v0.151.0 this weekend with a configurable grace period for MCP server tool discovery, making Codex more tolerant of slow-starting MCP servers. Anthropic is adjusting limits; OpenAI is reducing friction. Different levers, same developer-experience beat.

The builder's move: check your Claude Code usage before September 14. If you regularly hit the weekly ceiling, plan your heaviest sessions before the switchover. For long-running agent loops, recalibrate now rather than after the cutover.

xAI, Grok Bot
Grok Bot Gets a Social Feed

The technical story behind xAI's weekend push is the Grok Bot and X native integration. Users connect their X account from inside Grok Bot; xAI provisions a developer account automatically if needed. Paid Grok Bot subscribers receive complimentary X API credits at launch. A connected Bot can search X posts, read the user's timeline, check mentions, and surface real-time activity.

The mechanism: authenticated, account-aware X API access as a native Grok Bot skill. Not a web scrape. Not a generic search. A real-time, credentialed read of the user's X environment. That distinction matters.

The template-sharing mechanic is familiar to anyone who watched the GPT Store launch. What xAI adds is integration depth: a Grok Bot template that includes X account access is not just a configuration bundle, it is a real-time data connection to the user's social graph. Instructions told a model how to behave. This integration tells the model what you are actually doing right now on X. That is a different kind of product.

The pattern: this is the first AI agent product with first-party social network integration that its maker owns end to end. Anthropic, OpenAI, and Google all offer web search and third-party connectors. None of them own a social feed. xAI does. The integration is not a connector; it is a vertical. Grok 4.7, the 2.1-trillion-parameter model expected late August, did not ship in this window. Third-party coverage puts the slip to early September.
