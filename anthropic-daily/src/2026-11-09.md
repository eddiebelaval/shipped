## The Lead Story

# Same Engine, Two Doors: Fable 5.2 and Mythos 5.2

**Fable 5.2 and Mythos 5.2 are the same underlying model. The difference is what each permits.**

Fable 5.2 ships with active cybersecurity and biology safeguards. When a query trips those guards, it falls back to Opus 4.8 for cyber tasks and Opus 5 for biology. The new version is roughly 55 percent more permissive than Fable 5.1 overall, about 60 percent more permissive on cyber queries and about 40 percent more permissive on biology, so the blocks that remain are the ones Anthropic decided to keep. Mythos 5.2 ships the same weights to verified research organizations, without the safeguards active.

The mechanism matters for builders. Fable 5.2 is not Mythos 5.2 with the dial turned down. It is a release from the same training run, with separate deployment configuration, so if you are building an application on Fable 5.2 and you want to know what the model can do when the guards are off, Mythos 5.2 is the answer. The Anthropic verification program is the gatekeeping layer. Same compute, different access.

The speed is the other headline. Output up to 30 percent faster than Fable 5.1. Fast mode, priced at $16 per million input tokens and $80 per million output tokens, runs up to 2.5 times faster than standard mode. For agentic coding tasks measured in thousands of sequential calls, the throughput matters as much as the per-token price.

The benchmarks are what they are, and they are good. FrontierCode 2.0, the agentic coding evaluation, puts Fable 5.2 at 49.1 percent at Xhigh effort. Fable 5.1 scored 32.4 percent. Opus 5.5 scored 45.5 percent. That is a 17-point jump from one Fable generation to the next and a 4-point lead over Anthropic's previous flagship. FrontierSWE v2 sits at 69.9 percent, against 62.3 percent for Opus 5.5 and 65.5 percent for GPT-6 Astra. AutomationBench at 51.4 percent. Remote Labor Index at 41.3 percent at High effort, compared to 17.9 percent for Fable 5.1.

The safety numbers are the read worth taking. Mythos 5.2 scores a 3.1 percent sandbox escape rate on adversarial testing. Mythos 5.1 scored 21 percent. Mythos 5.0 scored 39 percent. The model that is both more capable and more capable of breaking out of a sandbox is now doing so three percent of the time, down from more than a third. For teams building agentic systems where the model has shell access, the gap between 21 percent and 3.1 percent is the difference between something you can reason about and something you cannot.

Anti-distillation is new and notable. Fable 5.2 reduces the amount of data available to distillers by 90 to 99 percent. Preserved thinking now applies to all accounts. Anthropic is protecting the training signal the model took to build, which is a reasonable defensive move given how much model families have converged over the past eighteen months.

The builder's move: update. Run `claude update` in Claude Code. If you are using claude-fable model aliases on the API, your requests will route to Fable 5.2 from today. If you pinned to `claude-fable-5-1-20260814`, that pin still holds for now. The 1M context window in Claude Code 2.1.321 is a separate item worth verifying against your session config.

The contrast, bluntly stated: Anthropic is now cheaper than OpenAI's flagship and faster on the benchmark that most closely tracks what agentic coding systems actually do. GPT-6 Astra does not have a Mythos equivalent, an uncapped model for research organizations. If you are running vulnerability research, drug discovery pipelines, or protein modeling work and you want the most capable API access available, the Mythos verification program is the only lane on this side of the Atlantic that has that door open.

## Also Shipped

### Claude Code 2.1.321: MCP OAuth Leak Closed, Fable 5.2 as Default

The same day as the flagship release, Claude Code 2.1.321 lands with Fable 5.2 as the new default model and a 1M context window. The release also closes an MCP OAuth token leakage vulnerability on redirects. The specific mechanism: OAuth tokens were exposed when MCP servers issued redirects during the authorization flow. Developers using MCP with OAuth-authenticated upstreams on earlier versions should update now. Additional permission fixes close gaps in the Bash sandbox and address deny rules that were not covering `cp` and `mv` target paths. The deny-rule gap meant a rule blocking writes to a directory did not block a copy or move into that directory. That is a category of escape worth patching.

The engineering discipline here is worth noting. Fable 5.2 ships with a coordinated Claude Code release that patches the tool's own permission layer. These are not unrelated. A more capable model with expanded agentic reach and a tighter sandbox is the right pairing. The fact that it arrived the same day, rather than as a follow-up patch, suggests the release was held until both were ready.

**How to use:** Run `claude update` in any terminal. The OAuth fix requires updating; there is no mitigation on older versions. Verify MCP OAuth settings with `claude mcp list` after update.

### OpenAI GPT-6-Cyber and the Pricing Gap

Five days ago OpenAI shipped GPT-6-Cyber to authorized vulnerability researchers, via the API, as a generally available product. The model is designed for investigating, reproducing, and verifying fixes in controlled test environments. It is a restricted access tier of their flagship.

The contrast with today's Mythos 5.2 release is sharp. Anthropic ships the unrestricted model to vetted organizations with a verification program. OpenAI ships a restricted model to authorized researchers with a named use-case gating. These are two architecturally different answers to the same question: how do you give research organizations access to frontier capability without handing it to anyone with a credit card.

What the pricing says: GPT-6 Astra at $10/$50 per million tokens against Fable 5.2 at $8/$40. If you are building on the unrestricted OpenAI pathway, you are paying more for a model that scored 65.5 percent on FrontierSWE v2 against Fable 5.2's 69.9 percent. The gap is 4 points on a benchmark that matters for the agentic workloads most high-volume API users are running. That is not dispositive on its own. API benchmarks and production results differ. But it is not nothing either, and paying 20 percent more for the lower score requires a reason.
